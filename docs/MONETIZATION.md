# 수익화 계획 (하고봐 플러스)

아직 아무것도 팔지 않고, 아무 기능도 잠그지 않았어요. 이 문서는 유료화를 켤 때의 설계예요. `PLANNING.md` 8장(무료 플랜은 앱 2개까지)은 이 문서로 바꿔요. 지금 있는 기능은 줄이지 않아요.

먼저 확인할 것: **군 복무 중 영리 행위(유료 판매, 사업자 등록)는 소속 부대(인사·법무)에 먼저 확인해야 해요.** App Store의 유료 앱 계약에는 세금·은행 정보가 필요해요. 확인 전에는 아래 단계를 진행하지 않아요.

## 1. 상품 (예시 가격)
| 상품 | 가격 | 메모 |
|---|---|---|
| 플러스 연간 | 29,000원 (월 약 2,400원) | **7일 무료 체험은 연간에만** |
| 플러스 월간 | 3,900원 | 체험 없음 |
| 플러스 평생 | 59,000원 | 한 번 결제 (비소모성) |

- 세 상품 모두 **가족 공유** 켜기.
- 실제 가격은 App Store Connect 가격 단계에서 가장 가까운 값으로 정해요.
- 구독 그룹 이름: `하고봐 플러스`. 상품 ID 예: `plus_yearly`, `plus_monthly`, `plus_lifetime`.

## 2. 무료 vs 플러스
원칙: **지금 있는 핵심 기능은 계속 무료**예요. 플러스는 새로 만드는 기능만 넣어요. 밖에 쓰는 문구는 "지금은 모든 기능 무료"로 해요. "평생 무료"라고 약속하지 않아요(얼리버드 약속은 따로).

| 기능 | 무료 | 플러스 |
|---|:-:|:-:|
| 앱 잠그기 (스크린타임, 개수 제한 없음) | ✓ | ✓ |
| 카메라로 푸시업·스쿼트 세기, 탭으로 세기 | ✓ | ✓ |
| 운동으로 시간 충전, 난이도, 최대 충전량 | ✓ | ✓ |
| 비상 5분 (하루 1번) | ✓ | ✓ |
| 오늘·주·월 기록, 연속 일수, "하나, 둘" 구령 | ✓ | ✓ |
| 운동 추가 (런지, 플랭크, 버피) | | ✓ |
| 잠금 시간표 (밤에는 충전해도 안 열리게) | | ✓ |
| 앱마다 다른 충전 비율 (쇼츠는 더 비싸게) | | ✓ |
| 주간 리포트와 자세한 기록 | | ✓ |
| 홈·잠금 화면 위젯 (남은 시간) | | ✓ |
| 구령 목소리 고르기 | | ✓ |

코드: `mobile/src/core/plan.ts`의 `PLUS_FEATURES`. 지금 `isPlus()`는 항상 `true`예요.

## 3. 결제창을 띄우는 때
1. **첫 충전 직후** (완료 화면): "충전 완료" 다음에 한 번. 닫기 버튼을 크게 둬요.
2. **플러스 기능을 누를 때**: 그 기능 설명과 함께.
3. **온보딩 끝에 1번**: "나중에"를 먼저 보이게.

띄우지 않는 때: 잠금 화면, 운동 중, 비상 5분을 쓸 때. 같은 사람에게 3일에 1번이 넘지 않게 해요.

## 4. 얼리버드 (유료화 전 설치자 = 플러스 평생 무료)
- **판정**: StoreKit 2 `AppTransaction.originalAppVersion` = 이 사람이 처음 받은 빌드 번호(`CFBundleVersion`)예요. iOS 16 이상에서 쓸 수 있고 앱 최소 버전이 iOS 18이라 모두 해당돼요. "처음 받은 빌드 < 결제가 들어간 첫 빌드"면 얼리버드예요.
- **빌드 번호**는 EAS `autoIncrement` + 원격 버전(`appVersionSource: remote`)이라 계속 올라가기만 해요. 18, 19, …
- **결제는 새 빌드와 함께 켜요** (OTA로 켜지 않음). 그래야 빌드 번호만으로 "켜기 전 설치"가 깔끔하게 나뉘어요. 같은 빌드 안에서 켜면 그 빌드를 받은 사람이 섞여요.
- **테스트**: TestFlight·샌드박스에서는 `originalAppVersion`이 항상 `"1.0"`이에요. 그래서 거기서는 모두 얼리버드로 나와요. 결제 흐름은 숨은 개발 메뉴(설정 제목 7번 탭)의 강제 전환으로 샌드박스에서 테스트해요.
- **읽는 방법**: RevenueCat `CustomerInfo.originalApplicationVersion`(RevenueCat의 기존 사용자 우대 방식)을 쓰거나, `AppTransaction.shared`를 부르는 작은 Expo 모듈을 써요. 판정 결과는 기기에 저장하고, 한 번 얼리버드면 다시 묻지 않아요.
- **예비 근거** (Apple 기록을 못 읽을 때):
  - `firstOpenedAt`: 이 폰에서 처음 연 시각이에요. 이미 저장했어요(OTA). 기기 밖으로 안 나가고, 한 번 정하면 바뀌지 않아요. 기존 사용자는 가장 오래된 운동 기록 날짜로 채웠어요. 데이터 초기화를 하면 같이 지워지고 그때부터 다시 기록돼요(개인정보처리방침대로).
  - 운동 기록 날짜: 최근 120일치가 기기에 있어요.
  - 코드: `isEarlyBird()` (`mobile/src/core/plan.ts`). 지금은 `PAID_LAUNCH = null`이라 모두 얼리버드예요.
- **밖에 하는 약속**은 유료화를 켤 때 처음 해요. 예: "유료화 전에 설치한 분은 플러스 평생 무료".

## 5. RevenueCat 구현 단계 (네이티브 → 새 빌드 + 심사)
1. App Store Connect: 유료 앱 계약, 세금·은행 정보 (군 확인 뒤). 구독 그룹과 3개 상품을 만들어요. 연간에 7일 무료 체험(도입 혜택)을 넣고 가족 공유를 켜요.
2. RevenueCat: 프로젝트와 iOS 앱을 만들고 App Store Connect 인앱 결제 키를 연결해요. 권한(entitlement) `plus`, 오퍼링 `default`(연간·월간·평생)를 만들어요.
3. 앱: `react-native-purchases`(+ 결제창은 `react-native-purchases-ui` 또는 직접 만들기)를 넣어요. 로그인 없이 익명 사용자로 써요. 공개 SDK 키만 앱에 넣어요.
4. `isPlus()` = `plus` 권한이 있거나 얼리버드. 오프라인일 때는 마지막 결과를 써요.
5. 개인정보처리방침과 App Store 개인정보(데이터 수집) 항목을 고쳐요(아래 6).
6. `docs/SUBMIT.md`의 "다음 네이티브 변경 때 할 일"(확장 빌드 번호)도 이 빌드에 같이 넣어요.
7. TestFlight 샌드박스 테스트: 구매, 체험, 복원, 해지, 가족 공유, 얼리버드 강제 전환.
8. 심사 제출: 첫 인앱 상품은 앱 버전과 함께 제출해야 해요. 심사 메모에 테스트 방법을 적어요.
9. 승인 뒤 출시. 그 빌드 번호를 `PAID_LAUNCH.firstPaidBuild`에 적어요.

## 6. 바꿔야 하는 문서
- **개인정보처리방침**: 4항 외부 서비스에 RevenueCat(구매 확인, 익명 ID)을 추가하고, 결제는 Apple이 처리한다고 써요. 5항 "분석 도구 없음"은 RevenueCat을 구매 확인에만 쓰면 그대로 둬도 돼요.
- **App Store Connect 앱 개인정보**: "데이터 수집 안 함"을 "구입 항목(사용자와 연결 안 됨, 앱 기능)"으로 바꿔요(RevenueCat 안내대로).
- **사이트·스토어 문구**: 가격 안내와 얼리버드 약속을 넣어요.

## 7. 유료화 순서
1. 부대 확인 → 2. 유료 앱 계약·세금 → 3. 상품·RevenueCat 설정 → 4. 결제 빌드(얼리버드 판정 포함) → 5. 샌드박스 테스트 → 6. 심사 → 7. 출시와 얼리버드 약속 공지 → 8. 2주 동안 지표를 보고 결제창 시점·체험 길이 조정

## 8. 출시 뒤 볼 지표
분석 도구를 넣지 않고 볼 수 있는 것만 써요. 개인정보 약속은 그대로예요.
- **App Store Connect 앱 분석**: 제품 페이지 전환율(노출 → 다운로드), 1·7·30일 보존율(동의한 사용자), 크래시
- **RevenueCat**: 체험 시작 수, 체험 → 유료 전환율(목표 30% 이상), 결제창 → 구매 전환율, 월 반복 매출, 해지율, 환불
- **리뷰·문의 메일**: 잠금 우회 문의, 카운트 불만
