# 한국판 Pushscroll 기획서 (v0.1)

> 작성일: 2026-11-14 · 상태: 초안 (의사결정 필요 항목은 맨 아래 정리)
>
> 웹 디자인 프로토타입: https://hagobwa.higgsfield.app (소개 페이지 + 클릭형 앱 화면 + 웹캠 푸시업 카운트 + 사전 알림)

---

## 1. 한 줄 정의

**"운동하고 봐."** — 숏폼·SNS 앱을 잠가두고, 푸시업·스쿼트를 해야만 시청 시간을 충전해 주는 앱.
카메라 자세 인식이 횟수를 세고, 1회 = 1분처럼 운동량이 곧 스크린타임 잔고가 된다.

## 2. 레퍼런스: Pushscroll 분석

| 항목 | 내용 |
|---|---|
| 핵심 메커니즘 | 선택한 앱 차단 → 운동으로 잠금 해제 (푸시업 1회 = 1분) |
| 운동 종류 | 푸시업, 스쿼트, 런지, 점핑잭, 다이아몬드 푸시업, 싯업, 플랭크 등 |
| 횟수 인식 | 카메라 포즈 인식(Pose detection)으로 자동 카운트 |
| 부가 기능 | 앱별 시간 제한, 스트릭, 진척도, Apple Health 연동, 위젯, 그룹 챌린지 |
| 수익 모델 | 무료 다운로드 + 구독(무료 체험 후 결제) |
| 플랫폼 | iOS 중심 |

**시사점**
- "벌칙(차단)"이 아니라 "거래(운동 ↔ 시간)"라는 프레이밍이 핵심. 죄책감 대신 보상감을 준다.
- 같은 콘셉트의 후발 앱(Repscroll, Push Up Time, ScrollFit 등)이 이미 다수 → **콘셉트 자체는 차별점이 아님.** 한국 시장에 맞춘 현지화와 플랫폼 커버리지가 승부처.

## 3. 왜 한국인가

- **과의존 지표**: 2025년 스마트폰 과의존 실태조사(과기정통부·NIA, 2026.3 발표) 기준 과의존 위험군 22.7%, 10대는 약 43%로 평균의 2배.
- **숏폼 이용률**: 청소년·성인 숏폼 이용률 95% 안팎, 2024년 조사에서 숏폼 이용자의 23%가 "이용시간 조절이 어렵다"고 응답.
- **자기관리 앱 문화가 이미 있음**: 열품타(공부 타이머+앱 잠금), 챌린저스(돈 걸고 습관 만들기), 캐시워크(걸음 수 리워드) 등이 성공 → "나를 통제해 주는 앱"에 대한 수용도가 높음.
- **안드로이드 비중이 높음** (갤럭시 점유율 높음) → iOS 중심인 해외 경쟁 앱이 비어 있는 자리.

## 4. 타깃 사용자

| 페르소나 | 상황 | 핵심 니즈 | 우선순위 |
|---|---|---|---|
| **A. 20~30대 직장인/대학생** | 퇴근 후·자기 전 쇼츠 2시간 순삭, 운동은 매번 미룸 | 폰 시간 줄이기 + 운동 습관을 한 번에 | **1순위 (MVP)** |
| **B. 수험생/공시생** | 공부 중 폰 만지는 습관 | 강제 차단 + 쉬는 시간 관리 | 2순위 |
| **C. 학부모 (자녀 폰 관리)** | 자녀 유튜브·게임 시간 갈등 | "운동하면 게임 시간" 같은 합의 가능한 규칙 | 3순위 (v2, 법적 검토 필요) |

## 5. 핵심 사용자 흐름

```
[온보딩]
목표 설정(하루 사용 목표 시간) → 잠글 앱 선택(유튜브/인스타/틱톡 등)
→ 권한 허용 → 첫 운동 체험(푸시업 5개) → "5분 충전 완료!"

[일상 루프]
잠긴 앱 실행 → 차단 화면 "푸시업 10개 하고 10분 보기"
→ 운동 화면(카메라, 자동 카운트, 음성 구령) → 시간 충전
→ 앱 사용 → 잔고 소진 시 다시 차단
```

## 6. 기능 정의

### 6.1 MVP (v1.0)

| 기능 | 설명 |
|---|---|
| 앱 차단 | 사용자가 고른 앱을 차단. 잔고가 있을 때만 사용 가능 |
| 시간 잔고(충전식) | 운동량을 분 단위 잔고로 적립·차감. "충전"이라는 한국형 표현 사용 |
| 운동 인식 | **푸시업, 스쿼트** 2종으로 시작 (정확도 확보가 우선) |
| 환산 비율 | 기본: 푸시업 1회 = 1분, 스쿼트 1회 = 0.5분. 난이도(쉬움/보통/빡셈) 3단계 |
| 음성 카운트 | 한국어 "하나, 둘, 셋…" + 마지막 3개 응원 멘트 |
| 비상 해제 | 하루 1~2회 "급한 일" 해제(30초 대기 + 사유 선택). 이탈 방지용 안전판 |
| 기록/스트릭 | 일별 운동량·절약 시간·연속 일수 |
| 홈 위젯 | 남은 잔고, 오늘 운동량 |

### 6.2 한국형 차별화 (v1.1 ~ v1.5)

| 기능 | 왜 한국에서 먹히나 |
|---|---|
| **음성팩: "조교 모드" / "PT쌤 모드" / "엄마 잔소리 모드"** | 밈·바이럴 포인트. 숏폼 홍보 소재로 바로 쓸 수 있음 |
| **카카오톡 공유 & 친구 랭킹** | "이번 주 푸시업 랭킹 1위" 인증 카드 → 자연 유입 |
| **크루 챌린지** | 친구·회사·학교 단위 주간 목표. 동아리·헬스 커뮤니티 확산 |
| **걸음 수로 충전** | 푸시업이 어려운 사용자 대응. 헬스 커넥트/HealthKit 연동 |
| **공부로 충전(수험생 모드)** | 영단어 퀴즈·타이머 집중 시간으로 충전 → 페르소나 B 공략 |
| **시즌 이벤트** | 수능 끝, 신년 결심(1월), 여름 바디프로필 시즌 |

### 6.3 이후 검토 (v2)

- 자녀 관리 모드 (부모 폰에서 자녀 규칙 설정) — 만 14세 미만 법정대리인 동의 등 법적 검토 필수
- 보증금 챌린지(챌린저스 방식) — 사행성·전자금융 관련 법률 검토 필수
- 포인트 → 기프티콘 리워드(앱테크) — 단가·어뷰징 리스크 검토 필요
- 운동 종류 확장: 플랭크(시간 기반), 런지, 버피, 싯업

## 7. 기술 설계

### 7.1 플랫폼 전략: **iOS + 안드로이드 동시 지원 필수**

한국은 안드로이드 비중이 높아, 해외 경쟁 앱처럼 iOS만 내면 시장 절반 이상을 놓친다.

| 영역 | iOS | Android |
|---|---|---|
| 앱 차단 | Screen Time API (FamilyControls, ManagedSettings, DeviceActivity) | AccessibilityService 또는 UsageStatsManager + 오버레이(SYSTEM_ALERT_WINDOW) |
| 사전 승인 | **Family Controls 배포용 Entitlement를 Apple에 별도 신청**해야 함 (승인까지 수주 소요 가능 → 가장 먼저 신청) | 접근성 API 사용 시 **Google Play 정책 신고 + 앱 내 명확한 고지** 필수 |
| 포즈 인식 | Apple Vision (사람 신체 포즈) 또는 MediaPipe | ML Kit Pose Detection 또는 MediaPipe |
| 헬스 연동 | HealthKit | Health Connect |
| 주요 리스크 | 차단 화면(Shield)에서 우리 앱으로 바로 이동하는 데 제약 → 알림 탭 등으로 우회 필요 (PoC로 검증) | 삼성·제조사 배터리 최적화가 백그라운드 서비스를 종료시킴 → 온보딩에서 "배터리 최적화 제외" 안내 필수 |

### 7.2 앱 구조 제안

- **크로스플랫폼 UI (Flutter 또는 React Native) + 네이티브 모듈**
  - 차단 기능은 어차피 각 OS 네이티브(Swift extension / Kotlin service)로만 구현 가능
  - 운동 화면·기록·소셜 등 나머지 UI는 공용 코드로 개발 속도 확보
- **포즈 인식은 MediaPipe Pose Landmarker로 통일**하면 양 플랫폼 카운팅 로직을 공유 가능
- **카메라 영상은 기기 안에서만 처리, 서버 전송·저장 없음** → 개인정보 리스크 최소화, 마케팅 포인트로도 활용

### 7.3 횟수 카운트 로직 (푸시업 예시)

```
관절 좌표(어깨·팔꿈치·손목·엉덩이·발목) 추출
→ 팔꿈치 각도 계산
→ 상태 머신: UP(>150°) → DOWN(<90°) → UP 이면 1회
→ 부정행위 방지:
   - 전신(어깨~발목)이 화면에 보여야 카운트
   - 몸통 일직선 여부(어깨-엉덩이-발목 각도) 체크
   - 1회 최소 소요 시간(예: 0.6초) 미만이면 무효
   - 신뢰도(visibility) 낮은 프레임 무시
```

- 스쿼트: 무릎 각도 + 엉덩이 높이로 동일 방식.
- **정확도 목표: 실측 대비 오차 ±5% 이내**를 MVP 출시 기준으로 설정. 다양한 체형·조명·폰 거치 각도로 테스트셋 구축.

### 7.4 백엔드

- MVP는 **로컬 우선** (잔고·기록 모두 기기 저장) → 서버 없이 출시 가능
- 소셜(랭킹/크루) 단계부터 Firebase 또는 Supabase 도입
- 인증: 카카오 로그인 + Apple 로그인 (iOS에서 소셜 로그인 제공 시 Apple 로그인 필수)

| 개인정보(카메라) 우려 | 신뢰 저하 | 온디바이스 처리 명시, 영상 미저장, 개인정보처리방침 명확화 |
| 미성년자 사용 | 법적 | v1은 만 14세 이상 대상, 자녀 모드는 법률 검토 후 |

## 15. 의사결정이 필요한 항목

1. **첫 출시 플랫폼**: iOS·안드로이드 동시 vs. 안드로이드 먼저 (Entitlement 대기 리스크 고려)
2. **개발 스택**: Flutter vs. React Native vs. 완전 네이티브
3. **MVP 타깃**: 페르소나 A(직장인/대학생) 단일 집중 vs. 수험생 모드까지 포함
4. **브랜드명** 최종 선택
5. **가격**: 위 가격안 수용 여부, 무료 플랜 범위
6. **팀 구성**: 1인 개발인지, 디자이너/마케터 합류 여부 → 로드맵 기간 조정
